## 1. The Big Picture: What is De Novo Genome Assembly?

### Reference-Based Alignment vs. De Novo Assembly
To understand genome assembly, we must first contrast it with **reference-based alignment**:

* **Reference-Based Alignment:** When a high-quality "gold standard" genome sequence (a **reference genome**) already exists for a model organism (such as humans or mice), raw sequencing reads can simply be aligned or mapped onto that reference template. This allows scientists to identify small single-nucleotide differences, small insertions, or small deletions.
* **De Novo Genome Assembly:** *De novo* comes from the Latin meaning "from the beginning" or "from scratch". **De novo genome assembly** is the process of reconstructing an organism’s complete, contiguous genome directly from raw, unordered sequencing reads **without using any pre-existing reference genome**.

```
Reference Alignment:    Reads ──► [ Align to Reference Template ] ──► Find Small Variants

De Novo Assembly:       Reads ──► [ Find Overlaps & Build Graphs ] ──► Reconstruct Genome from Scratch
```

---

### Why De Novo Assembly Matters
1. **Non-Model & Novel Organisms:** Millions of species (wild plants, newly discovered bacteria, rare animals) have no reference genome. De novo assembly is the only way to map their genetic code.
2. **Uncovering Population Diversity:** Even within species with a reference genome (like humans), relying solely on one reference template misses large genomic variations unique to different human populations.
3. **Detecting Complex Structural Variants:** Large chromosomal rearrangements, inversions, and multi-kilobase duplications are extremely difficult to detect by simple alignment, but become clearly visible when full contigs are assembled from scratch.
4. **Tracking Evolution & Disease:** Assembly enables researchers to track evolutionary divergence over time and serves as a cornerstone for personalized medicine.

> 💡 **Real-World Analogy:** Imagine putting together a 10,000-piece jigsaw puzzle.
> * **Reference Alignment** is like having the completed picture printed on the box top. You look at a puzzle piece, find its location on the picture, and place it there.
> * **De Novo Assembly** is like solving the puzzle when someone threw away the box top. You have no picture to guide you—you must compare the edges of every piece to every other piece to figure out how they connect.

> 💬 **In Simple Terms:** Reference alignment compares DNA pieces against a pre-existing map. De novo assembly builds the map from scratch because no map exists.

## 2. Third-Generation Sequencing: Oxford Nanopore Technology (ONT)

### How Nanopore Sequencing Works
The demonstration utilizes sequencing data generated by **Oxford Nanopore Technology (ONT)**, a prominent **third-generation sequencing** platform.

1. **Physical Pore:** Long strands of DNA are extracted and passed physically through a microscopic synthetic protein channel called a **nanopore** embedded in a membrane.
2. **Electrical Current:** An electric potential is continuously applied across the nanopore, creating a steady ionic current.
3. **Base Sensing:** As individual DNA bases (**A**, **C**, **G**, **T**) pass through the physical pore, each base obstructs the pore differently, causing distinct, measurable changes in electrical amperage.
4. **Base Calling:** Computer algorithms interpret these real-time current fluctuations to read the exact sequence of DNA letters.

```
DNA Strand ──► [ Protein Nanopore ] ──► Ionic Current Amperage Fluctuations ──► Digital Read
```

---

### Simplex vs. Duplex Reads
ONT sequencing generates two main types of read data:

* **ONT Simplex Reads:** Generated when only **one** of the two complementary DNA strands passes through the nanopore.
* **ONT Duplex Reads:** Generated when **first one strand** passes through the nanopore, immediately followed by its **reverse complementary strand** passing through the exact same pore.

```
Simplex Read:  5'- A C T G C A T G -3' ──────────────────────────────────────────► Read 1 Only

Duplex Read:   5'- A C T G C A T G -3' ──(Forward)──┐
                                                    ├──► Combined Consensus (Higher Accuracy!)
               3'- T G A C G T A C -5' ──(Reverse)──┘
```

#### Why Duplex Reads Matter
Because both strands of the same physical DNA molecule are read sequentially, the sequencing software cross-checks the two signals to cancel out noise, yielding **substantially higher accuracy** per read while maintaining long read lengths.

---

### Long Reads Guarantee Higher Assembly Contiguity
* **Second-Generation Sequencing (e.g., Illumina):** Produces very short reads (~150 to 300 base pairs). While accurate, short reads cannot span across long repetitive regions in genomes, resulting in fragmented assemblies.
* **Third-Generation Long Reads (ONT):** Produces reads that are tens to hundreds of kilobases long. Long reads easily bridge across repetitive DNA stretches, **guaranteeing dramatically higher contiguity** (fewer, longer continuous sequence blocks) in the assembled genome.

> 💬 **In Simple Terms:** Simplex reads sequence one strand of DNA. Duplex reads sequence both strands back-to-back, drastically reducing errors. Long nanopore reads act like gigantic puzzle pieces, making it much easier to build complete chromosomes without getting stuck on repetitive regions.

## 3. The Assembler: HiFiASM & String Graph Architecture

### What is HiFiASM?
**HiFiASM** is an end-to-end software assembler designed specifically for long-read sequencing data. It accepts raw sequencing reads in FASTQ or FASTA format and directly outputs assembled genome graphs.

```
Raw Reads (FASTQ/FASTA) ──► [ HiFiASM Assembler ] ──► Phased Contig Graphs (GFA)
```

---

### String Graphs vs. De Bruijn Graphs
Unlike standard assemblers that chop reads into tiny fixed-length \\(k\\)-mers to build De Bruijn graphs, HiFiASM uses a **String Graph** architecture:
* **Vertices:** Represent full, un-chopped sequencing reads.
* **Edges:** Represent direct **suffix-prefix overlaps** between pairs of individual reads.
* **Advantage:** Preserves the full length and contextual integrity of long reads without losing long-range information.

---

### Phased Assemblies & Diploid Genomes
Human cells (and many model organisms) are **diploid**, meaning they carry **two copies of each chromosome**—one inherited from the mother (maternal haplotype) and one from the father (paternal haplotype).

* **Unphased Assembly:** Collapses maternal and paternal chromosomes into a single artificial "average" sequence.
* **Phased Assembly:** HiFiASM separates maternal and paternal genetic variations to produce **two distinct sets of contigs (Haplotype 1 and Haplotype 2)**, each guaranteed to represent a true parental chromosome.

```
Diploid Organism ──► Maternal Chromosome 18 ──► Haplotype 1 Contigs (hp1)
                 ──► Paternal Chromosome 18 ──► Haplotype 2 Contigs (hp2)
```

---

### Software Benchmarking & Historical Landmarks
As highlighted in the demonstration table, HiFiASM stands out because it is highly accurate, fast, memory-efficient, and natively capable of generating phased contigs:
* **CHM13 Benchmark:** HiFiASM was a primary tool used to generate the historic **first complete Telomere-to-Telomere (T2T) assembly** of the human CHM13 sample.
* **HG002 Diploid Benchmark:** More recently, advanced pipelines (such as Verkko) built upon these principles to achieve T2T assemblies for diploid human genomes like HG002.

## 4. Dataset Overview & The N50 Statistic for Reads

### The Demonstration Dataset
The walkthrough utilizes an ONT duplex dataset sampled from the first **10 million base pairs (10 Mb)** of human **Chromosome 18** from the HG002 sample:

* **File Format:** Compressed FASTQ (`reads.chr18.10m.fastq.gz`).
* **Read Count:** ~12,000 sequences.
* **Shortest Read:** 512 base pairs.
* **Longest Read:** 123,000 base pairs (123 kb).
* **Average Read Length:** ~27,000 base pairs (27 kb).

---

### Step-by-Step Breakdown: What is Read N50?
To summarize read lengths, bioinformaticians use the **N50 statistic**.

#### How to Calculate Read N50:
1. Take all sequencing reads and sort them in **decreasing order of length** (longest to shortest).
2. Calculate the **total cumulative length** of all reads combined.
3. Calculate **50% of the total cumulative length** (the target threshold).
4. Walk down the sorted list of reads, summing their lengths one by one.
5. The length of the specific read that pushes the cumulative sum across the 50% threshold is the **Read N50**.

```
Sorted Reads:  [  123 kb  ] [  80 kb  ] [  50 kb  ] [  27 kb  ] ... [ 0.5 kb ]
Cumulative:    123 kb ────► 203 kb ───► 253 kb ───► 280 kb ───► ... 324 Mb Total
                                           ▲
                                    50% Threshold (162 Mb)
                                    N50 Read Length = 50 kb
```

> 💡 **Real-World Analogy:** Imagine you have 100 wooden planks of various lengths totaling 1,000 feet. You sort them from longest to shortest and start laying them end-to-end. The plank you lay down at the exact moment you reach 500 feet (50% of total length) defines your N50 value. If that plank is 15 feet long, your N50 is 15 feet.

> 💬 **In Simple Terms:** N50 is a weighted median. It tells you that half of your total sequencing data is contained in reads that are at least as long as the N50 value.

## 5. Step-by-Step Execution of HiFiASM

### The Command Line Execution
The demonstration runs HiFiASM using the following bash command:

```bash
hifiasm -o test -t 32 reads.chr18.10m.fastq.gz
```

#### Command Options Breakdown:
* `hifiasm`: Executes the HiFiASM assembler executable.
* `-o test`: Specifies the **output prefix**. All generated output graph files will start with `test.` (e.g., `test.raw.unitig.gfa`).
* `-t 32`: Allocates **32 CPU threads** for parallel computation to speed up assembly.
* `reads.chr18.10m.fastq.gz`: The input gzipped FASTQ file containing raw ONT duplex reads.

---

### Internal Log Progression: What HiFiASM Does Under the Hood

```
1. K-mer Spectrum Analysis ──► 2. Read Error Correction (3x) ──► 3. All-Pairs Overlap Computation
                                                                             │
                                                                             ▼
5. Primary & Phased Contigs ◄── 4. Processed Unitig Graph ◄── 4. Raw Unitig Graph Generation
```

#### Step 1: K-mer Spectrum Analysis
HiFiASM begins by counting all unique fixed-length \\(k\\)-mers in the read dataset to plot a **\\(k\\)-mer frequency distribution (spectrum)**:
* *Example from log:* The log reports 39,840 \\(k\\)-mers occurring exactly 10 times, and 390,389 \\(k\\)-mers occurring exactly 28 times.
* *Purpose:* Distinct frequency peaks in the \\(k\\)-mer graph allow HiFiASM to mathematically infer the **homozygous coverage** (shared sequences present on both parental chromosomes) and **heterozygous coverage** (parent-specific sequence variants).

#### Step 2: Read Error Correction (3 Rounds)
By default, HiFiASM runs **3 iterative rounds of error correction** on the raw reads. After each round, it re-plots the \\(k\\)-mer spectrum to verify that random sequencing noise is decreasing and true coverage peaks are sharpening.

#### Step 3: All-Pairs Suffix-Prefix Overlap Computation
Once reads are error-corrected, HiFiASM compares all reads against each other to identify all matching **suffix-prefix overlaps**.

#### Step 4: Graph Construction & Simplification
* **Raw Unitig Graph:** Built directly from all overlapping read pairs.
* **Processed Unitig Graph:** HiFiASM simplifies the raw graph by evaluating read coverage depth at each node to pop/remove small bubbles caused by heterozygous variants or residual noise.

#### Step 5: Output Generation
HiFiASM outputs the primary assembly graph along with two partially phased haplotype graphs.

## 6. Graph File Formats & Visualization with Bandage

### What is GFA Format?
HiFiASM outputs assembly graphs in **GFA (Graphical Fragment Assembly)** format. GFA is a tab-delimited plain-text standard for storing genome graphs.

```
S   Segment_ID   Sequence_Content    [Optional Tags]
L   From_ID      From_Orient (+/-)   To_ID   To_Orient (+/-)   Overlap_Info
a   Unitig_ID    Read_ID_1           Read_ID_2                 ...
```

#### Key Line Types in GFA:
* **`S` (Segment Lines):** Represents graph nodes (unitigs or contigs).
  * *Column 1:* `S`
  * *Column 2:* Segment ID (e.g., `h1tg1L`)
  * *Column 3:* The actual DNA sequence string (`ATCG...`)
* **`L` (Link Lines):** Represents directed edges between segments.
  * *Column 1:* `L`
  * *Column 2 & 3:* Source Segment ID and orientation (`+` or `-`)
  * *Column 4 & 5:* Target Segment ID and orientation (`+` or `-`)
  * *Column 6:* CIGAR string describing overlap length
* **`a` (Annotation Lines):** Lists the specific raw read IDs that were merged to form that segment.

---

### Visualizing Graphs with Bandage
**Bandage** (**B**ioinformatic **A**pplication for **N**avigating **D**e Novo **A**ssembly **G**raphs **E**asily) is an interactive GUI software used to load and visualize GFA files.

```
Load GFA File ──► Click "Draw Graph" ──► Customize (Node Width/Colors/Labels) ──► Save Image
```

#### Visual Progression Across Graph Stages in the Demo:

| Assembly Stage File | Node Count | Structural Characteristics & Observations |
| :--- | :---: | :--- |
| **Raw Unitig Graph** (`*.r_utg.gfa`) | Multiple | Complex tangled network containing two major connected components and small bubbles representing maternal/paternal differences. |
| **Processed Unitig Graph** (`*.p_utg.gfa`) | Few | Considerably simplified. Coverage depth filtering popped small heterozygous bubbles. |
| **Primary Assembly** (`*.p_ctg.gfa`) | **1 Node** | Fully resolved into **1 single continuous 9.9 Mb contig** covering the full 10 Mb target region. |
| **Haplotype 1 Graph** (`*.hap1.gfa`) | **3 Nodes** | Total length 10.6 Mb: One dominant **9.9 Mb contig** plus two tiny unattached fragments (35 kb and 55 kb). |
| **Haplotype 2 Graph** (`*.hap2.gfa`) | **2 Nodes** | Total length 9.9 Mb: Split into two large contigs (**8.0 Mb** and **1.9 Mb**). |

> 💬 **In Simple Terms:** GFA is a text file listing the puzzle pieces (`S`) and which pieces connect to which (`L`). Bandage takes that text file and draws it as an interactive visual map so you can see your assembled chromosomes.

## 7. Quality Evaluation & QUAST Analysis

### Key Assembly Evaluation Metrics
How do we know if an assembly is high quality? Bioinformaticians compute five core metrics:

1. **Total Assembly Length:** Should closely match the expected biological size of the genome or target chromosome (~10 Mb in this demo).
2. **Number of Contigs:** Measures fragmentation. Fewer contigs indicate a more contiguous, high-quality assembly.
3. **Longest Contig Length:** The length of the largest single continuous piece. Larger is better.
4. **Contig N50:** The length of the shortest contig at 50% of the *total assembled length*.
5. **Contig NG50:** The length of the shortest contig at 50% of the ***estimated reference genome size***.

---

### N50 vs. NG50: Why NG50 Matters
* **N50 Problem:** If an assembler produces a severely incomplete assembly (e.g., assembling only 1 Mb out of a 10 Mb genome into a single 1 Mb contig), its N50 will artificially look like 100% (1 Mb).
* **NG50 Solution:** By using the known or estimated reference genome size (\\(G = 10\text{ Mb}\\)) as the baseline denominator, **NG50 allows fair, unbiased quality comparisons** across different assemblers and different datasets.

```
N50 Baseline  = 50% of Total Assembled Length  (Can be misleading if assembly is incomplete)

NG50 Baseline = 50% of Estimated Genome Size   (Standardized & comparable across tools)
```

---

### Converting GFA to FASTA using `awk`
Evaluation tools like QUAST require inputs in **FASTA format**. Because GFA files contain link lines (`L`), they must first be converted into clean FASTA files using an `awk` command:

```bash
awk '/^S/ {print ">"$2"\n"$3}' test.hap1.gfa > test.hap1.fasta
```

#### Command Logic Breakdown:
* `/^S/`: Scans the GFA file and filters only lines that start with `S` (Segment lines).
* `print ">"$2`: Prints a FASTA header line starting with `>` followed by column 2 (the Segment ID, e.g., `>h1tg1L`).
* `"\n"$3`: Prints a newline followed by column 3 (the raw DNA sequence string).
* `> test.hap1.fasta`: Redirects the output into a new FASTA file.

---

### Running QUAST
The demonstration runs **QUAST** (**Q**uality **A**ssessment **T**ool for Genome Assemblies) using `quast.py`:

```bash
quast.py -t 32 -o test.hap1.stats --est-ref-size 10000000 --large test.hap1.fasta
```

#### Parameter Breakdown:
* `-t 32`: Allocates 32 CPU threads.
* `-o test.hap1.stats`: Output directory for report files.
* `--est-ref-size 10000000`: Sets the estimated reference size (\\(10\text{ Mb}\\)) required to compute **NG50**.
* `--large`: Optimizes QUAST algorithms for large eukaryotic genomes.

#### Summary of Demonstration QUAST Results:

```
Haplotype 1 Assembly:  3 Contigs  | Total: 10.6 Mb | Max Contig: 9.9 Mb | N50/NG50: 9.9 Mb
Haplotype 2 Assembly:  2 Contigs  | Total:  9.9 Mb | Max Contig: 8.0 Mb | N50/NG50: 8.0 Mb
```

## 8. Alignment & Comparative Visualization: IGV & SAFIRE

Once contigs are assembled, bioinformaticians align them back to reference genomes to inspect correctness and discover structural variations.

### Method 1: Alignment Visualization via IGV
To view contigs alongside raw reads, the demonstration uses **Minimap2** and **IGV** (Integrative Genomics Viewer):

```
Contigs (FASTA) + Reference ──► Minimap2 (-x asm5) ──► SAM File ──► BAM ──► Sort & Index ──► IGV
```

#### Minimap2 Command:
```bash
minimap2 -a -x asm5 reference.fa test.hap1.fasta > aln.sam
```
* `-a`: Generates output in **SAM** (Sequence Alignment Map) format.
* `-x asm5`: A preset optimized for aligning assembly contigs to a reference genome of the same species (<5% sequence divergence).

#### Post-Processing Pipeline:
1. Convert SAM to binary **BAM** format (`samtools view -b`).
2. **Sort** the BAM file by genomic coordinates (`samtools sort`).
3. **Index** the BAM file (`samtools index`).
4. Load reference, raw reads, and sorted BAM contigs into **IGV**.

#### IGV Observations:
In IGV, assembled contigs align smoothly across Chromosome 18. Small random sequencing errors present in raw reads disappear in the contigs because HiFiASM’s consensus algorithm successfully corrects them. True biological insertions/deletions shared across reads are preserved in the final contig.

---

### Method 2: Structural Variation Visualization via SAFIRE
For whole-genome comparative analysis, the demonstration presents **SAFIRE**, an interactive web-based synteny visualization tool.

```
Syntenic / Co-linear Alignment (Blue Blocks) ──► Contig & Reference share same orientation

Inverted Alignment (Yellow Blocks)           ──► Contig sequence is INVERTED relative to reference!
```

#### Key SAFIRE Observations:
* **Chromosome 18 Analysis:** When aligning whole-genome HG002 contigs against the CHM13 human reference, SAFIRE shows large contigs spanning 17 Mb to 80 Mb seamlessly.
* **Chromosome 11 Structural Inversion:** Zooming into Chromosome 11 reveals **blue blocks** (co-linear sequence) interrupted by a prominent **yellow block**. The yellow block highlights a true **chromosomal inversion** where a multi-megabase segment in the HG002 sample is flipped 180 degrees relative to the CHM13 reference.
* **Complex Rearrangements:** Non-contiguous, multi-colored alignment blocks highlight complex structural variations where the sample diverges significantly from the reference template.

> 💬 **In Simple Terms:** IGV lets you zoom in to inspect individual DNA base letters. SAFIRE gives you a satellite view of whole chromosomes, using blue blocks for matching sequences and yellow blocks to flag giant flipped (inverted) DNA segments.

## The 5 Most Important Things to Remember

1. **De Novo Assembly Requires No Reference:** It reconstructs genomes from scratch, making it essential for non-model organisms and discovering complex structural variants.
2. **Long Duplex Reads Drive High Contiguity:** ONT duplex reads provide long lengths (>27 kb average) and high consensus accuracy, enabling assemblers to span repetitive DNA.
3. **HiFiASM Generates Phased Assemblies:** It uses a string graph architecture to separate maternal and paternal chromosomes into two distinct haplotype contig sets.
4. **GFA to FASTA Conversion is Required for Evaluation:** Graph output (`.gfa`) must be converted to sequence format (`.fasta`) using tools like `awk` before running evaluation suites like QUAST.
5. **NG50 Standardizes Quality Evaluation:** Unlike standard N50, NG50 evaluates assembly contiguity relative to the estimated total genome size, preventing incomplete assemblies from inflating scores.

---

## Common Misconceptions & Confusing Points

* ❌ **Misconception 1: De novo assembly is only useful when no reference genome exists.**
  * *Correction:* De novo assembly is also vital for species with existing reference genomes because it uncovers population-specific diversity and complex structural variants that simple reference alignment misses.
* ❌ **Misconception 2: N50 and NG50 are the exact same metric.**
  * *Correction:* N50 calculates 50% based on the *total assembled length* of the contigs. NG50 calculates 50% based on the *estimated total genome size*, making NG50 comparable across different tools and incomplete assemblies.
* ❌ **Misconception 3: Bandage alters the underlying graph topology if you re-layout or drag nodes.**
  * *Correction:* Moving or dragging nodes in Bandage only changes the 2D visual layout on screen. The underlying graph topology (vertices and edges) remains 100% identical.
* ❌ **Misconception 4: GFA files can be directly passed into QUAST for quality metrics.**
  * *Correction:* GFA files contain link lines (`L`) and graph metadata. They must be parsed into standard FASTA format (e.g., using `awk '/^S/ ...'`) before QUAST can process them.
